# MODIS MCD43A4 v061 nadir BRDF-adjusted reflectance (`modis-mcd43a4-v061`, via `microsoft-planetary-computer`)

**What:** the daily MODIS Terra+Aqua NBAR (nadir BRDF-adjusted reflectance) at 463 m on the MODIS sinusoidal grid (10° tiles, 2400 × 2400 px, sphere R = 6 371 007.181 m, latitude = WGS84 geodetic). Each day's value comes from a kernel-driven BRDF model (RossThick–LiSparse-Reciprocal). That model is inverted from all cloud-free, atmospherically corrected Terra and Aqua observations in a 16-day window, weighted towards the centre day, and evaluated for a nadir view with the Sun at the local-noon zenith angle of the centre day. It covers land and shallow/inland water. Deep ocean is fill (32767). Scale factor 1e-4. The files state a valid range of 0–32766.

**Citation:** Schaaf, C. & Wang, Z. (2021). MODIS/Terra+Aqua BRDF/Albedo Nadir BRDF Adjusted Ref Daily L3 Global - 500m V061. NASA EOSDIS LP DAAC. DOI [10.5067/MODIS/MCD43A4.061](https://doi.org/10.5067/MODIS/MCD43A4.061). Algorithm: Schaaf, C. B. et al. (2002). First operational BRDF, albedo nadir reflectance products from MODIS. *Remote Sensing of Environment* 83, 135–148. DOI [10.1016/S0034-4257(02)00091-3](https://doi.org/10.1016/S0034-4257(02)00091-3). NASA data policy: no restrictions.

**Access (no login):** the Microsoft Planetary Computer holds cloud-optimized GeoTIFF copies, one COG per band (collection `modis-43A4-061`). Citation: Microsoft Open Source et al. (2022), microsoft/PlanetaryComputer, Zenodo DOI [10.5281/zenodo.7261897](https://doi.org/10.5281/zenodo.7261897). Items come from the STAC API (`/api/stac/v1/search`): first the latest item, to find the most recent day, then all items of that day. Both responses are saved and hashed. Blobs are read with the anonymous SAS token from `/api/sas/v1/token/modiseuwest/modis-061-cogs`. The token is a URL signature, so it is passed as request parameters and never written to the ledger (`download.fetch(record_url=...)`).

**Reading (`surf_cog.py`):** for each band file, two HTTP Range requests go through `download.fetch`: the first 32 KiB, which hold the IFDs, and the contiguous byte span of the first overview's tiles. Each ledger entry records the range, the remote size, the ETag and Last-Modified. Tiles are deflate-decoded in Python. The first overview is 1200 × 1200 px at 926.6 m. The files' GDAL `IMAGE_STRUCTURE` metadata states `OVERVIEW_RESAMPLING=CUBIC`. We tested this on tile h19v04 band 1: the overview matches a 2 × 2 block mean of the full-resolution image to 16 DN (0.0016) mean absolute difference, against 71 DN for nearest-neighbour. The cubic filter preserves the mean (block-mean difference < 0.01 %). Near dark or fill pixels it rings slightly: 0.08 % of values fall below 0, median −0.0008. These values are kept, so texel averages stay unbiased. Downloads are about 6 MB per tile (three bands), and the files are deleted after decoding.

**Use (`surf_earth.py`, layer `albedo`):** bands 3 (459–479 nm, centre 469), 4 (545–565, 555) and 1 (620–670, 645). Every overview pixel centre is mapped exactly to its level-4 texel: the sinusoidal inverse gives geodetic latitude, which is converted to planetocentric. The pixel is box-averaged, separately for MOD44W land and water pixels. Water pixels are used only where OC-CCI has no value. Labels: brightness **measured**; colour **estimated**, because three bands 86–90 nm apart fail the dense-sampling criterion (see `surf_color.py`). The flat hold beyond 645 nm misses vegetation's red edge (> 690 nm), which carries little weight in x̄ and ȳ.

**Epoch:** the build uses the most recent day on the Planetary Computer. The first build used A2026257: centre 2026-09-14, window 2026-09-06 to 2026-09-21, 315 tiles.
